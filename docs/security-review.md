# 账号与同步服务安全检查

检查日期：2026-10-05。范围为当前后端代码、实际 Linux 服务配置及已部署 HTTPS 接口；这是一轮基础检查，不是渗透测试或合规认证。

## 已验证的保护

- 公网 HTTPS 证书可信，HTTP 自动重定向到 HTTPS；账号响应不缓存。
- 公网探测仅确认 22、80、443 可达；API 的 8787 和 Caddy 管理接口的 2019 不对公网开放。
- SSH 使用公钥认证，禁止空密码、密码登录及 root 直接登录；admin 的密钥连接和 sudo 权限已重新验证。
- 后端以独立 needtodo 用户运行，启用只读系统目录、隔离临时目录、保护用户目录及禁止新增权限。数据库目录为 700，数据库及备份文件为 600。
- 每个账号通过会话绑定 UID，客户端提交的账号字段不能改变数据所属账号。数据库使用参数化查询，已验证账号隔离、未登录访问拒绝和同步版本冲突检测。
- 密码使用随机盐及 scrypt，当前配置为 N=32768、r=8、p=3，符合 OWASP 的 32MiB 推荐组合；旧账号在成功登录后自动升级，保持账号 ID、已有数据和密码不变。
- IP 注册／登录限制为每分钟 25 次；单个账号登录每分钟 15 次，限制计算同时最多两个密码哈希，避免小内存服务器堆积密码计算任务。
- 会话令牌使用 32 字节随机数，服务端只存 SHA-256 摘要，30 天到期，退出时撤销。客户端使用系统安全存储保存令牌。
- 删除任务只保留 ID、删除状态和更新时间。服务器也会精简旧客户端重新上传的删除记录，不保留其中的标题、分类和提醒内容。保留这些标记用于避免旧设备再次上传已删除任务。
- SQLite 启用 secure_delete，并定期通过 backup API 制作一致备份。每日自动备份保留约七天，备份不对公网提供下载。

参考：[OWASP 密码存储指南](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)、[OpenSSH 服务配置](https://man.openbsd.org/sshd_config)。

## 当前边界

日程同时保存在客户端及云端同步副本中。数据库和本机 JSON 没有应用层加密，云同步不是端到端加密；拥有服务器管理权限的人仍能读取云端日程。因此不能宣称服务器管理员无法查看数据。

旧的本机或服务器备份可能仍包含删除前的任务内容，直到备份按保留策略清理。用户指定的迁移前后手动备份不属于每日自动清理范围，便于恢复。

尚未实现邮箱验证、双因素认证和登录设备管理。GitHub 绑定已配置并启用，使用一次性授权状态及 S256 PKCE，账号身份读取权限为 read:user，不申请仓库权限；服务器不保留 GitHub 访问令牌。账号与 GitHub 一对一绑定，只有绑定账号可使用云同步。GitHub 找回流程验证已绑定身份后，允许十分钟内使用一次性票据重置密码；重置撤销全部旧会话，保留账号 ID 和已有数据。已测试授权重放、并发重置与重复绑定拒绝。完整真实授权仍需由用户在软件中完成一次。

如需要更高的数据保密等级，应另行设计客户端加密、密钥备份与跨设备恢复流程，不能仅靠 HTTPS 或修改文件权限实现端到端保密。
